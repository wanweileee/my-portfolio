What I'm building

A multi-step agent that reads a BigQuery warehouse loaded by Fivetran, autonomously surfaces statistically significant customer cohorts using Gemini plus classical statistics, picks the right activation channel per cohort, and routes campaign drafts to humans for one-click Slack approval.

Why this problem

Marketing ops at most PLG SaaS companies ship 2–4 personalization campaigns per quarter. Their warehouses contain 30+ untapped cohorts. The gap isn't creativity or tooling. It is human cognitive throughput.

Most "AI marketing" tools attack the wrong end of that gap: they make it faster to write a campaign, but the bottleneck is finding the cohort worth writing for in the first place. LLMs that can reason about structured data and call tools are the first reasonable shot at automating the discovery step itself, not just the copy.

Design decisions and why

Three-layer safety architecture: deterministic → LLM with verification → human-only. Statistical evaluation runs in pure Python with a hard p-value gate. Drafting uses Gemini with safety filters. Final approval is human.

The reason this matters: if I let the LLM judge "is this cohort significant?", I'd ship campaigns based on noise. The LLM is bracketed on both sides by code I can verify, which keeps it useful without being load-bearing for correctness. Trust is allocated to the part of the system that can actually be wrong about it.

Channel selection is rules, not LLM. "Should this go to email or push?" is deterministic. It depends on cohort recency, 30-day email engagement, and value tier. Making it an LLM call would add latency, cost, and non-determinism. Worse, when something goes wrong you can debug a rule; you can't really debug "why did the model pick push here?" without an expensive eval harness.

Every LLM-generated SQL goes through a validator. SELECT-only, allowlisted tables, ≤1 GB scan, must include the outcome column. If validation fails, a template library takes over. LLM-generated SQL is one of the most demo-killing failure modes. A runaway scan or an accidental mutation could cost real money and leak data. The agent should never crash because Gemini wrote bad SQL.

Mocked destination APIs with real payloads. Braze, OneSignal, Meta Ads, and Salesforce calls write a realistic JSON request to local logs and return a fake ID. The demo's value is the agent's behavior, not whether Braze actually sends. This also lets me build the full agent flow without standing up five trial accounts.

Vertex AI Python SDK over Agent Builder. Agent Builder is great for chatbot/RAG patterns but not for a structured discovery pipeline with statistical evaluation. The SDK gives procedural control over orchestration and full access to Gemini's safety settings, function calling, and structured output. The right tool for orchestration-heavy work.
